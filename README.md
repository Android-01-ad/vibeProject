# BibeProject 로직 정리

이 프로젝트는 Unity 기반의 로그라이크 덱 전투 프로토타입입니다. 현재 구조는 역할별로 로직을 분리해서 유지하고 있으며, 특히 다음 구분이 핵심입니다.

- 게임 흐름 제어: `RoguelikeGameManager`
- 카드/덱 관리: `DeckManager`
- 플레이어 상태/상호작용: `PlayerCharacter`
- 카드 데이터 모델: `CardDefinition`
- 필드 오브젝트 처리: `ObstacleObject`, `TreasureChestObject`
- 직업별 스프라이트 처리: `PlayerClassSpriteController`

이 구조를 통해 메인 매니저가 덱 규칙까지 직접 다루지 않고, 각 담당 기능이 분리됩니다.

## 주요 스크립트

### 1. `Assets/script/RoguelikeGameManager.cs`
게임 전체 흐름을 관리하는 메인 매니저입니다.

- 런 시작 및 초기화
- 전투 / 보상 / 보스 스테이지 전환
- 적 턴 처리
- 보상 카드 선택 처리
- 승리와 패배 판정
- 개발자 모드 입력 처리
- 덱 관리자 연동

핵심 역할:
- 스테이지 흐름 제어
- 보상 선택 및 다음 층 이동
- 전반적인 게임 상태 관리

### 2. `Assets/script/DeckManager.cs`
카드 덱과 상위 카드 보관을 전담하는 관리자입니다.

- 하위 카드: 드로우 덱 / 보유 덱 / 버리기 덱 관리
- 상위 카드: 장비 영역 / 도구 영역 관리
- 같은 이름 카드 중복 획득 시 강화 처리
- 드로우 덱 소진 시 버리기 덱 재셔플
- 카드 사용 시 버리기 덱 이동

핵심 역할:
- 덱 규칙과 카드 분류 분리
- 하위 카드와 상위 카드의 소속을 엄격하게 구분

### 3. `Assets/script/PlayerCharacter.cs`
플레이어의 체력, 공격, 직업, 카드 사용 상호작용을 담당합니다.

- Warrior / Mage 직업 선택
- 직업 전환 로직
- 장비 및 도구 계열 카드 조건 기반 직업 전환
- 체력 회복 및 공격력 반영
- 적 공격/피해 처리
- 필드 오브젝트와 카드 사용 처리

핵심 역할:
- 플레이어 상태 관리
- 전투 및 필드 상호작용 구현

### 4. `Assets/script/CardDefinition.cs`
카드의 기본 데이터를 담는 모델입니다.

- 카드 이름
- 설명
- 카드 등급: `Lower` / `Upper`
- 강화 단계 (`UpgradeLevel`)
- 표시 이름 (`DisplayName`)
- 효과 강도 계산 (`Power`)

핵심 역할:
- 카드 자체의 데이터 저장
- 하위/상위 카드 구분
- 중복 수집 시 강화 반영

### 5. `Assets/script/CardCatalog.cs`
CSV 카드 데이터를 읽어 카드 풀을 구성하는 유틸리티입니다.

- `cards.csv` 로드
- CSV 파싱
- `CardDefinition` 생성
- Tier(하위/상위) 인식

핵심 역할:
- 카드 풀 생성
- 외부 데이터 기반 카드 초기화

### 6. `Assets/script/PlayerClassSpriteController.cs`
플레이어의 직업별 스프라이트 전환을 담당합니다.

- Warrior 스프라이트 관리
- Mage 스프라이트 관리
- 직업 전환 시 스프라이트 적용

핵심 역할:
- 직업 시각 표현 분리
- 직업별 아트 처리

### 7. `Assets/script/DeckScreenController.cs`
덱 UI 화면을 제어하는 컨트롤러입니다.

- 보유 덱 표시
- 드로우 덱/버리기 덱 상태 표시
- 덱 화면 열기/닫기

핵심 역할:
- UI 렌더링 및 표시 관리

### 8. `Assets/script/EnemyCharacter.cs`
적 캐릭터의 상태와 행동을 관리합니다.

- 체력 관리
- 공격력 관리
- 플레이어 공격 반응
- 적 사망 상태 체크

핵심 역할:
- 적 전투 동작 처리

### 9. `Assets/script/BossCharacter.cs`
보스 전용 캐릭터입니다.

- 보스 공격 패턴
- 보스 사망 시 이벤트 전파
- 최종 승리 조건 처리

핵심 역할:
- 보스 전투 감지 및 종료 판정

### 10. `Assets/script/BossStageIntro.cs`
보스 스테이지 입장 연출용 스크립트입니다.

- 보스 등장 텍스트 및 연출
- Animator 트리거 실행
- 카메라/애니메이션 연출 처리

핵심 역할:
- 보스 스테이지 입장 연출

### 11. `Assets/script/ObstacleObject.cs`
전투용 장애물 오브젝트입니다.

- 전투 카드 사용 시 파괴
- 파괴 애니메이션 재생
- 파괴 이펙트 실행
- 일정 시간 후 제거

핵심 역할:
- 전투 중 장애물 제거

### 12. `Assets/script/TreasureChestObject.cs`
탐험용 보물 상자 오브젝트입니다.

- 탐험 카드 사용 시 열림
- 오픈 애니메이션 재생
- 보상 이벤트 또는 파괴 처리
- 일정 시간 후 제거

핵심 역할:
- 보상 상자 상호작용 처리

## 핵심 설계 규칙

### 1. 카드 분류 규칙
- 하위 카드(`Lower`): 드로우 덱 / 보유 덱 / 버리기 덱에만 소속 가능
- 상위 카드(`Upper`): 장비 영역 / 도구 영역에만 소속 가능

이 규칙을 통해 카드가 덱과 장비 영역을 혼용하지 않도록 제한합니다.

### 2. 직업 전환 규칙
- 기본 직업은 `Warrior` 또는 `Mage` 중 하나
- 장비/도구 영역의 카드 이름과 설명을 기반으로 검사 계열 / 마법 계열 조건을 판별
- 조건에 따라 `Warrior` 또는 `Mage`로 전환

### 3. 덱 흐름 규칙
1. 보유 덱에 카드가 추가되면 드로우 덱이 재생성됩니다.
2. 드로우 덱이 비면 버리기 덱을 재셔플해 채웁니다.
3. 카드를 사용하면 버리기 덱에 추가됩니다.

### 4. 스테이지 흐름 규칙
- 전투 스테이지: 적을 쓰러뜨리는 구간
- 보상 스테이지: 보상 카드 선택 구간
- 보스 스테이지: 보스 전투 구간

## 설계 흐름

1. `RoguelikeGameManager`가 전체 스테이지와 턴을 제어합니다.
2. 보상 선택 시 `DeckManager`가 카드 추가 및 강화 로직을 처리합니다.
3. `PlayerCharacter`는 직업 전환, 공격, 회복, 필드 오브젝트 상호작용을 수행합니다.
4. `ObstacleObject`와 `TreasureChestObject`는 카드 종류에 따라 다른 동작을 수행합니다.
5. 보스/적/덱/UI는 기능별로 독립된 스크립트로 분리되어 있습니다.

## 폴더 구조 요약

- `Assets/script/` : 게임 로직 전반
- `Assets/StreamingAssets/` : 카드 CSV 데이터
- `Assets/` : 씬, 프리팹, 리소스 등

## 주의사항

- 새 스크립트 추가 시 Unity에서 다시 컴파일됩니다.
- 새 오브젝트에 `Animator`, `SpriteRenderer`, `ParticleSystem` 등이 연결되어 있어야 합니다.
- 보스/장애물/상자와 Animator 상태 이름이 정확히 일치해야 애니메이션이 정상 동작합니다.
- 상위 카드와 하위 카드는 각각 다른 보관 영역을 사용하므로, 카드 생성 시 Tier 지정이 중요합니다.
